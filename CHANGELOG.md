# Registro de avances de GlowCare

Este registro resume cinco avances realizados durante la asignatura. Corresponden a la planificación, análisis, diseño y documentación del proyecto; no representan funcionalidades implementadas.

| N.º | Avance o ajuste | Evidencia |
|---|---|---|
| 1 | Se creó el tablero Kanban y se organizaron las tareas con prioridades, roles responsables, fechas estimadas y estados de avance. | Documentos de las semanas II y VI y tablero de GitHub Projects. |
| 2 | Se definieron cinco historias de usuario, cinco requisitos funcionales y cinco no funcionales a partir de una encuesta. Se documentó su trazabilidad con los Issues #8 al #12. | Documento de la Semana III. |
| 3 | Se elaboraron los diagramas de casos de uso, clases, secuencia, colaboración y actividades para representar la estructura y el funcionamiento esperado del sistema. | Documento de la Semana IV e imágenes UML. |
| 4 | Se seleccionó una arquitectura por capas con separación entre frontend y backend, definiendo las responsabilidades de los componentes y la dependencia del servicio de pago externo. | Documento de la Semana V e Issue #13. |
| 5 | Se consolidaron las evidencias técnicas en la carpeta docs y se amplió el README con el objetivo, problema, funcionalidades previstas, arquitectura, herramientas, organización frontend/backend y estado actual. | Carpeta docs, README principal e historial de commits del repositorio. |

## Control de cambios

Las incorporaciones y modificaciones de archivos se registran mediante commits en GitHub. Los documentos de las semanas anteriores conservan el estado del proyecto en cada entrega.

La implementación y las pruebas del sistema permanecen pendientes.
